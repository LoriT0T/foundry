# Foundry V1

The second built version of Foundry — a clean superset of V0. Everything in this folder is real and in use. V1 adds exactly one dimension: the universal discipline of operating as an agent under **external, dynamic, project-specific regulation** — while carrying no actual rules, only the method for handling being regulated.

- **`BOOTSTRAP.md`** — the birth sequence + loading rule a fresh agent runs first. V1 adds one **mandatory birth question** — *"is this project regulated?"* — answered by a recognition check that routes a *yes* to the regulatory-architecture capability (and its research playbook) before building.
- **`foundation/`** — the *behavioral* branch: how an agent thinks and works. Loaded in full by every agent, always. (9 files: the execution loop, memory architecture, self-improvement, orchestration, reliability, the quality rubric, the red lines — now including a regulation red line — and two enforced build laws: compartmentalization and the mistake engine.)
- **`knowledge/`** — the *technical* branch: production capabilities. The index (`knowledge/INDEX.md`) is read at startup; individual capability files load **only when a task triggers them**. Spine: `INDEX.md`, `DECISION_RULE.md`, `tool-registry.md`, `INSTANTIATION_GUIDE.md`, `BOOTSTRAP_loading_section.md`. Capabilities: retrieval, guardrails, evaluation, observability, orchestration, deployment, the tool layer (MCP), memory systems, cost/routing, context engineering, and **regulatory architecture** (new in V1).

**What V1 adds over V0:** the `regulatory-architecture` capability — recognition, the recurring constraint categories framed as *questions* (never answers), a research-at-instantiation playbook, and the compliance-seam attachment pattern — plus a regulation red line in `foundation/RED_LINES.md` and the mandatory recognition question in the birth sequence. It carries **no regulation, no named regime, no sample rule** — those are the most project-specific thing there is, and the foundation stays bias-free. Loading is on-trigger: an agent in a non-regulated domain never loads the capability and behaves exactly as a V0-born agent.

**Where to start:** read `BOOTSTRAP.md`, then `knowledge/INDEX.md`. The two non-negotiable principles — *no bias* and *no authority over judgment* — are explained in the top-level README and on the site.
