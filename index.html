The two principlesThe non-negotiables that make the foundation reusable. ▸

1 No bias

The foundation carries zero project specifics — no domain, subject, person, or goal. Everything in it is universally true. Specifics enter only at instantiation, from the agent's own context, and flow outward into that agent — never back into the foundation. The test for anything in the branches: would this be equally true for an agent doing something completely different?

2 No authority over judgment

Every file is reference material an agent builds from, never an instruction it must obey. A file's completeness is not authority — the agent always decides whether to adapt a pattern, instantiate it, or build its own. Knowledge informs; it never commands.

The birth sequenceAn agent decides the hard questions before any code — a reviewable birth certificate. ▸
  1. The goal — in one sentence, with a concrete definition of what "working well" looks like.
  2. Judgment vs. determinism — where the work needs real judgment (reserve the model there) versus where it is rules and math (make that deterministic and reliable).
  3. The data sources — each distinct body of data the agent will work with, named.
  4. The irreversible & risky — anything that moves money, posts publicly, or deletes — gated behind a human or a hard limit.
  5. The cadence — how often it runs, and how it reports back.
The answers form a reviewable birth certificate: before the agent does anything, you can read exactly what it decided it is. Then it loads the behavioral foundation in full, reads the technical index, and instantiates each capability against its own context.
Foundry V0 — the foundation that exists todayTwo branches, the real file inventory, and the loading discipline. ▸

foundation/ — behavioral

How an agent thinks and works. Small, universal, loaded in full, every run. The execution loop, memory architecture, self-improvement, reliability, the red lines — plus two enforced build laws: compartmentalization, and a mistake-generalization engine that turns a single mistake into a rule its whole class can never repeat.

knowledge/ — technical

How an agent builds real systems. Larger, per-task, loaded only when a task triggers it — the index is read at startup; the capability files are not. Ten production capabilities, each documenting the current standard.

The file inventory — everything in V0 is published, exactly as it is used:

# foundry-v0/ BOOTSTRAP.md the birth sequence + the loading rule foundation/ behavioral · loaded in full THINKING.md MEMORY_ARCHITECTURE.md SELF_IMPROVEMENT.md ORCHESTRATION.md RELIABILITY.md QUALITY_RUBRIC.md COMPARTMENTALIZATION.md MISTAKE_ENGINE.md RED_LINES.md knowledge/ technical · loaded on trigger spine → INDEX.md DECISION_RULE.md tool-registry.md INSTANTIATION_GUIDE.md BOOTSTRAP_loading_section.md capabilities → retrieval guardrails evaluation observability orchestration deployment mcp-tools memory-systems cost-routing context-engineering

The loading discipline. Load all of foundation/, always — it is bounded and universal, so the cost is fixed and small. Read only the knowledge/ index at startup, and pull a capability file only when the task in front of you triggers it. The technical branch is open-ended; loading it wholesale would flood the context for no benefit. That asymmetry is why the two branches are kept separate, with separate rules.

How it corrected itself under real useThe credibility hook, in full: a flaw found and fixed at the root. ▸

The first real agent built on Foundry surfaced a genuine contradiction inside Foundry itself: one reference file instructed a write that a foundation red line forbids. Because the method treats a red line as overriding any reference file, the agent resolved it correctly in the moment — and the fix was then made permanent at the class level: every place the same pattern appeared was corrected, not just the one that surfaced. A methodology built to catch and repair its own flaws under real use did exactly that on first contact with reality.
